# EchoStream 基准测试

> 本机回环环境（macOS 26.5 arm64，release 构建，quinn 0.11），数据用于发布参考与优化跟踪。
> 运行：`cargo run -p echostream --example bench --release`

## 结果（2026-08 v0.2 基线：复用通道 + 连接池 + 大窗口）

| 指标 | 64B | 4KiB | 256KiB |
|------|-----|------|--------|
| 顺序 RPC 延迟（独立流） | ~50 µs/次 | ~87 µs/次 | ~2.45 ms/次 |
| 顺序 RPC 延迟（复用通道） | ~43 µs/次（-15%） | - | - |
| 并发 RPC 吞吐（独立流） | ~80k req/s | ~28k req/s | - |
| 并发 RPC 吞吐（复用通道） | ~127k req/s（+58%） | - | - |
| 并发 RPC 吞吐（连接池 4） | ~148k req/s（+85%） | - | - |
| 可靠事件吞吐 | ~204k evt/s | ~39k evt/s | - |
| 不可靠事件吞吐（数据报） | ~711k evt/s | ~405k evt/s（1KiB，受 datagram 4096 上限约束） | - |
| 流吞吐 | - | - | ~238 MiB/s（1MiB 帧） |

## 通信模型开销说明

- **RPC 复用通道**（默认）：一条长连接双向流按请求 id 多路复用，消除每请求的流打开/关闭
  与包开销 —— 吞吐 +58%、延迟 -15%；载荷 >64KiB 自动切换独立流避免队头阻塞
- **RPC 连接池**：`ClientBuilder::pool(n)` 多 QUIC 连接分摊流控窗口并跨核扩展
  （quinn 单连接为单任务处理）—— 4 连接吞吐 +85%
- **事件复用通道**：长连接单向流批量帧（可靠）；数据报（不可靠）吞吐为可靠通道 3.5x
- 传输调优：连接/流级接收窗口 16MiB/8MiB、并发流上限 4096（默认 64KiB/100 会在大载荷与
  高并发场景造成流控停顿与并发瓶颈）

## 说明

- 256KiB 顺序延迟为吞吐受限（2 × 256KiB 回环往返 ≈ 2.45ms，与单流吞吐 238MiB/s 吻合），
  大文件场景请使用流（Stream）模式或连接池
- 数据报载荷上限 = 对端通告的 `datagram_receive_buffer_size`（4096）

## 复现

```bash
cargo run -p echostream --example bench --release
```
